# 地图模块前后端接口文档

> **说明**
>
> - 目标明确为：**后端返回即可渲染的数据结构，前端不做路径计算，负责展示**。
> - 支持在地图上同时展示：**贴路网路线（polyline） + 沿线一个或多个电子围栏（circle / polygon）**。
>
> **核心能力**
>
> - `GET /api/routes/{id}/render`：一次请求返回路线 polyline + 点位 + 围栏几何。
> - 路线详情支持 `preview`（可选），用于路线详情页地图展示。
>

---

## 0. 总体设计原则（重要）

### 0.1 职责边界（前端 vs 后端）

**前端职责**
- 地图渲染（底图、缩放、覆盖物）
- 覆盖物绘制：
  - Polyline（路线）
  - Circle / Polygon（电子围栏）
  - Marker（点位）
- 列表与地图联动展示

**前端不做**
- ❌ 路线规划计算
- ❌ 距离/时长计算
- ❌ 调用腾讯 WebService（Direction / Geocoder）

**后端职责**

- 调用腾讯位置服务 WebService（Direction / 逆地理编码）
- 生成（可选：并缓存）贴路网 polyline
- 聚合 Route + Point + Fence，返回「可直接渲染」的数据

---

## 1. 核心使用场景

### 场景 A：路线列表（不画地图）
- 只展示路线名称、点位数量、人员分配（如果有）等
- **不需要 polyline**（LngLat[] | string）

### 场景 B：路线详情页（地图展示）
- 地图上展示：
  - 一条贴路网路线
  - 路线上各点位
  - 点位对应的电子围栏
- **需要 polyline + fence 几何**

本文档重点 **场景 B**。

---

## 2. 路线渲染聚合接口（核心）

### 2.1 接口定义

**GET** `/api/routes/{routeId}/render`

> 用途：  
> - 前端一次请求即可在地图上渲染完整路线视图  
> - 避免前端多接口拼装数据

---

---

### 2.3 字段说明（前端关注点）

#### route.polyline
- **贴路网路线**
- 来源：后端调用腾讯 Direction API（骑行）
- 前端用途：
  ```js
  new TMap.MultiPolyline({
    geometries: [{ paths: route.polyline }]
  })
  ```

#### route.bound
- 建议后端返回
- 前端可直接：
  ```js
  map.fitBounds(route.bound)
  ```

#### fences[]
- 电子围栏几何
- 前端按 `type` 判断渲染：
  - `CIRCLE` → `TMap.Circle`
  - `POLYGON` → `TMap.MultiPolygon`

## 3. 路线详情接口（可选）

### 3.1 轻量路线详情（不画地图）

**GET** `/api/routes/{id}`

返回：
```json
{
  "id": "route_001",
  "name": "本部-东区配送线",
  "travelMode": "BICYCLING",
  "points": [
    { "pointId": "point_001", "order": 1 },
    { "pointId": "point_010", "order": 2 }
  ]
}
```

---

### 3.2 路线详情 + 预览

**GET** `/api/routes/{id}?needPolyline=true`

```json
{
  "id": "route_001",
  "name": "本部-东区配送线",
  "travelMode": "BICYCLING",
  "points": [
    {
      "pointId": "point_001",
      "order": 1,
      "name": "本部",
      "location": { "lng": 116.39, "lat": 39.91 }
    }
  ],
  "preview": {
    "polyline": [{ "lng": 116.39, "lat": 39.91 }],
    "totalTheoryDistanceMeter": 6800
  }
}
```

> 说明：  
> - 此接口适合“路线详情页”
> - 若页面主要用于地图展示，**优先使用 `/render` 接口**

## 4. 前端渲染流程（示意）

```ts
// 1. 获取渲染数据
const { route, fences } = await api.getRouteRender(routeId)

// 2. 调整视野
map.fitBounds(route.bound)

// 3. 画路线
drawPolyline(route.polyline)

// 4. 画点位
route.points.forEach(drawMarker)

// 5. 画围栏
fences.forEach(drawFence)
```

---

## 5. 为什么不直接用“点位直线连接”

- 点位连线 ≠ 实际行走路径
- 会出现：
  - 穿楼
  - 穿河
  - 穿不可通行区域
- 本方案强制要求：
  - **polyline 必须来自腾讯 Direction API**
  - 前端只做渲染，不做规划

---

## 6. 后端实现建议（非前端关心，但利于对齐）

- 对 `/render` 接口结果进行缓存：
  - Key：`routeId + travelMode + pointsHash`
- 路线编辑后自动失效缓存
- polyline 推荐返回 **点集数组**，避免前端解码成本

---

## 7. 与 TS 类型文件的对应关系

- 本文档的 `RouteRenderDTO`
  ↔ `map-api.types.v2.ts` 中 `RouteRenderDTO`
- 本文档的 `RouteDetailDTO.preview`
  ↔ `map-api.types.v2.ts` 中 `RoutePreviewDTO`

## 8. 总结

> **路线 = 点位顺序（业务） + polyline（展示）**  
> **围栏 = 几何（circle / polygon）**  
> **前端 = 纯展示，后端 = 纯计算 + 聚合**
